# 請假模組前端 — 設計文件

日期：2026-11-25　狀態：已核准（含修訂：加登入畫面；主管即員工，不用身分切換）

## 1. 目的與為什麼

會計事務所內部系統的第一個模組。先做「請假」的可互動前端，讓團隊能實際點擊驗收 UI/UX，再接 FastAPI + PostgreSQL。
最終必須能產出符合勞基法的工時表，所以請假一律**以小時計**。

## 2. 目標 / 非目標 / 反目標

**目標**
- 員工：申請假單、撤銷假單、查看剩餘時數與假別、查看申請進度、查看自己的請假紀錄、查看公司行事曆（含國定假日）與同事已核准請假。
- 主管：查看自己與部屬的請假資訊、審核（核准 / 退回）部屬假單、審核撤銷申請。
- Apple 風格、人性化的介面與互動。
- Docker 包裝，`docker compose up` 即可開啟。

**非目標（這一輪不做）**
- 行政設定假別/時數、報表匯出、老闆全域視角與權限管理。
- 外出單、加班單、打卡、報帳、task。
- 真實後端、真正的身分驗證（登入畫面存在，但驗證是假資料）、資料持久化（重新整理後回到假資料初始狀態可接受；可選用 localStorage 保留操作）。

**反目標（做了也算失敗）**
- 看起來像傳統 ERP：密密麻麻的表格、一堆下拉選單、看不懂狀態。
- 員工送單後不知道「現在卡在誰那裡」。
- 時數計算錯誤或與勞基法規則矛盾。

## 3. 已決定的規則（使用者決定）

| 項目 | 決定 |
|---|---|
| 範圍 | 員工 + 主管 兩個角色 |
| 簽核 | 依天數分層：≤ 3 天（≤ 24 小時）直屬主管核准即生效；> 3 天需再送經理 |
| 職務代理人 | 必選，只通知不需同意；系統提醒代理人當期是否也請假 |
| 忙季 | 報稅季（5 月）等期間送單時提醒，不擋 |
| 技術做法 | A：Vite + React + TS + 假資料 API 層，nginx Docker |
| 登入 | 要有登入畫面 |
| 主管 | 主管也是員工：擁有全部員工功能，另外多出審核相關頁面（不做身分切換） |

## 4. 我做的判斷（可推翻）

- **撤銷規則**：待審 → 員工可直接撤回；已核准且未開始 → 送「撤銷申請」給主管確認；已過請假日 → 不可撤銷。
- **假別**（勞基法 / 勞工請假規則 / 性平法）：特休、事假（14 日/年，不給薪）、病假（未住院 30 日/年，半薪）、生理假（每月 1 日）、婚假（8 日）、喪假（依親等 3/6/8 日）、公假（依實際）、家庭照顧假（7 日，併入事假）、產假（8 週）、陪產檢及陪產假（7 日）。每種顯示剩餘時數與給薪說明；病假、喪假、婚假等標示「可能需附證明」（上傳欄位僅 UI，不真的上傳）。
- **單位**：最小 0.5 小時，一日 8 小時，上班 09:00–18:00，午休 12:00–13:00 不計。
- **出差**：不算公假，歸外出單（下一輪）。
- **組織假資料**：約 12 人，2 組，每組一位主管，上面一位經理。經理自己的假單由老闆（資料中存在，但本輪不做老闆畫面）審核。
- **登入**：員工編號 + 密碼。假驗證：所有示範帳號共用一組示範密碼，記在 `frontend/src/mock/README` 與登入頁的「示範帳號」小抽屜（可一鍵填入，方便驗收）。登入狀態存 localStorage，可登出。登入頁走 Apple ID 風格：置中單欄、大標題、密碼錯誤時欄位輕微搖晃。
- **持久化**：操作存在 localStorage，提供「重設示範資料」。

## 5. 方案比較

| 方案 | 取捨 | 結果 |
|---|---|---|
| A. React + 假資料 API 層 + 角色切換 | UI 可先定案；之後只換 API 函式實作即可接 FastAPI | **採用** |
| B. 前後端 + DB 一次接好 | 資料真實，但工時大半在後端，資料表需求還沒定 | 不採用 |
| C. 靜態 HTML 原型 | 最快但用完即丟 | 不採用 |

## 6. 畫面與流程

**全域**：登入頁 → 主畫面。左側欄（桌機）/ 底部 Tab（手機）；右上角頭像選單（姓名、職稱、登出）。導覽項目依登入者決定：一般員工看到員工四頁；主管與經理額外看到「待審核」（含數字徽章）與「團隊概況」。

**員工**
1. **總覽**：問候語 + 剩餘特休大數字；各假別剩餘時數卡片（環形進度）；「進行中的申請」卡片含追蹤式進度條（已送出 → 主管 → 經理 → 完成）。
2. **申請請假**（sheet 由下滑出）：選假別（卡片式，顯示剩餘）→ 選日期時間（全天 / 半天 / 自訂時段）→ 即時計算時數並顯示「申請後剩餘」→ 選代理人（顯示該期間是否有空）→ 事由 → 預覽簽核路徑 → 送出。忙季、超過剩餘、代理人衝突皆以內嵌提示呈現。
3. **我的紀錄**：依狀態分段（全部 / 審核中 / 已核准 / 已退回 / 已撤銷），點開看詳情與時間軸、撤回/撤銷按鈕。
4. **行事曆**：月曆，顯示國定假日、忙季區間、自己與同事已核准請假。

**主管（= 員工 + 以下頁面）**
1. **待審核**：卡片清單，每張顯示請假人、假別、時數、代理人、與同組同期請假衝突；核准 / 退回（退回需填原因）；撤銷申請也在此。
2. **團隊概況**：本週誰請假、部屬剩餘時數一覽。
3. 主管自己的假單照員工流程申請，送給他的上一層審核。

## 7. 視覺方向（Apple 風格）

系統字體堆疊（-apple-system, "SF Pro", "PingFang TC", "Noto Sans TC"）；大量留白、大標題；圓角 12–20px 卡片、極淺陰影與毛玻璃頂欄；單一強調色（iOS 藍）+ 語意色（綠 核准、橘 待審、紅 退回）；sheet / 彈簧動畫、`prefers-reduced-motion` 支援；淺色 / 深色模式跟隨系統；繁體中文、口語化文案（「送出後，王經理會收到通知」）。

